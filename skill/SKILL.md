# 台历日期校对

自带一套矢量解析引擎：不读文字、只读图形，靠"位置 + 顺序 + 历法"判断对错。
支持有无农历、红黑混排、表格线、上月末灰字、桌面台历版式；不依赖用户字体。

**三种版式都能认**（引擎自动判断，不用用户说明）：

| 版式 | 长什么样 | 判据 |
|---|---|---|
| 七列网格 | 最常见的月历，7 列 × 4~6 行 | 优先用版面上画好的**格子框**定位；没有框就按字号分层猜 |
| 横排一行 | 一整月 31 天横着排成一条 | 一条横带里 ≥10 个等距槽 |
| 横排连排 | 整月连着排、换行接着排（星期表头可能重复） | 先套版式档案；没有档案就做参数试算 |

**版式档案（profiles）**：认不出的新款式，引擎会在"哪几行是日期行 / 一格多宽"上试算，
切出来正好等于当月天数、且一位/两位分布符合历法时才认（自证不过就跳过，绝不报假错），
认对了就把几何参数存进 `profiles/*.json`；同一款再印时直接命中档案。
判断"这次是第一次见"还是"套了档案"，看 stdout 里有没有「套用档案」。

**图片也能直接校对**：png / jpg / 扫描件、手机截图都行。引擎会把图片当"一页稿子"，
自动二值化、按行列投影切字，后面的认形状、投票命名、对历法完全通用。
不需要联网、不需要 OCR 模型、不需要 API Key。

## 铁律

1. **读数只能来自 `result.json`**，不要凭图猜数字，也不要为了"让报告好看"而漏报。
2. 引擎报的错误就是错误，**不许自行降级或合并**；要判断"这是不是有意排版"就问用户，不要替用户决定。
3. 说结论用大白话，面向不懂代码的设计师：说"哪个月、哪一天、错在哪"，不要讲算法。
4. 报告必须**真的交付**给用户，不要只在回答里复述数字。

## 第一步：确认能跑

先看有没有现成解释器，按顺序挑第一个能用的：

- Windows 便携版：`<项目目录>\runtime\python\python.exe`（自带依赖，最稳）
- Linux/macOS：`python3`
- Windows 其他：`py -3` / `python`

确认依赖（缺就装，别跳过）：

```bash
<解释器> scripts/probe_env.py
# 若 ok=false，按它给的 fix 装：<解释器> -m pip install pymupdf numpy pillow
```

装不上或没有 Python → 走 `references/环境准备.md`，并把情况如实告诉用户（不要假装跑过）。

## 第二步：跑校对

```bash
<解释器> scripts/run_check.py "<PDF 或图片路径>" --year 2027 --png --diag
```

参数说明：

- `--year` 必填，**不知道年份就问用户**（年份错了整份结论都是错的）
- `--first-col auto` 默认自动判第一列是周一还是周日；用户明确说了才改
- `--start-month 1` 第 1 个月历页对应几月；稿子里有"从 3 月开始"这种才改
- `-o` 输出目录，默认在 PDF 旁边生成 `<文件名>_校对/`
- `--png` 导出每页原图 + 标注图（诊断时才需要）
- `--diag` 导出每格明细 `cells.csv`（诊断时才需要）

stdout 第一行是 JSON 摘要，完整结果在 `<输出目录>/result.json`。

## 第三步：看体检结果

`result.json` 里的 `health.need_ai` 就是"这次读懂了没有"：

- `need_ai: false` → 引擎正常，直接按 `n_error` / `n_warn` 给结论并交付报告。**不要再多此一举去诊断。**
- `need_ai: true` → 按 `health.reasons` 进入第四步。

体检口径：

| 字段 | 含义 |
|---|---|
| `pages_read` / `pages_skipped` | 认出月历的页数 / 跳过的页数 |
| `skipped_pages` | 每页跳过的原因（封面、广告页、字形太少、位图……） |
| `thin_months` | 某月格子数明显少于当月天数（切分漏了格子） |
| `min_conf` | 最低读数置信度 |
| `expected_but_empty` | 该有日期却是空的格数 |
| `shape_groups` | 全本归出的形状种数（正常 9~12）；明显偏大说明切碎，偏小说明粘连 |

注意：**首/末页被跳过通常是封面封底，属正常**；夹在月历页中间的页被跳过才算问题。

## 第四步：引擎失灵时怎么办（这是本 Skill 的价值所在）

不要一上来就说"这稿子我读不了"。按 `references/诊断手册.md` 的四步走：

1. **看 `result.json` 的 `skipped_pages` 原因和 `health` 数值**，先归类到手册里的根因表。
2. **看 `pages/pNN_原页.png` 和 `pages/pNN_标注.png`**（`--png` 产物）：原图看版式，标注图看引擎把框画到哪儿了——**标注错位本身就是线索**。
3. **看 `cells.csv`**：每格的读数/应为/置信度，能看出是"根本没切出格子"还是"切了但读错"。
4. 定位到根因后，**改 `calproof/` 里的对应函数**（手册里给了每个根因对应哪个文件哪个函数），改完必须重跑验收稿；
   若某款版式以前没见过，引擎会自动试算并存档 `profiles/*.json`，下次同类稿子直接命中。

修好后要向用户交代三句话：**这是稿子的问题还是工具的问题**、**工具现在能认了**、**以后同类稿子会自动认出来**。

## 交付

- 报告是单个 HTML，直接交付 `result.json.report_html`。
- 回答里先说结论（几个月、几个错误），再逐月列错误；**不要**把 12 页逐页流水账抄一遍。
- 如果错误是"某天印在了首行最左边/对角线/格子里没有它"这类，提醒用户这可能是版式的有意写法，让他决定要不要忽略。

## 已知盲区（不要承诺能做）

- **照片质量差**（手抖虚焦、灯光反光、日期压在深色花纹上）：位图切字会切碎或粘字，报告会出现成片"待确认"。让用户重拍 / 扫描 / 提供原始 PDF。
- **一份文件里塞了两套版式**（如 24 页 = 横排 12 个月 + 网格 12 个月）：月份会按页序对错，暂时不支持；请用户分开导出。
- **双月一页、竖排周历、一格一周的周历**：暂不支持。
- **农历/节气内容本身的错别字**、节假日调休标记的**位置**：暂不校对。
- **日期印在格子外面**（压在两格之间的格线上，如"24 | 31 | 25"）：引擎会报成"这一格空了 / 缺日期"，要如实告诉用户这是位置异常。

## 引擎版本

`result.json.engine` 是引擎指纹。仓库根目录的 `calproof/` 与 `skill/engine/calproof/` 应是同一份代码：

- 指纹一致 → 两边同步
- 不一致 → 以仓库里那份为准，用 `scripts/sync_engine.ps1 -Project <仓库根目录>` 同步
