# 诊断手册：引擎读不懂一份稿子时

目标：**用最少的手工侦查，把根因归到下面 10 类里的一种**，然后改一处、验三份。

> 路径说明：本仓库的引擎在**仓库根** `calproof/`。Skill 里跑的时候，把 `calproof/`
> 复制成 `skill/engine/calproof/`（或跑 `skill/scripts/sync_engine.ps1 -Project <仓库根>`）。
> 下文说 `xxx.py` 都指 `calproof/xxx.py`。

## 零、先分类：读不出来 vs 读错了

| 现象 | 看哪里 | 说明 |
|---|---|---|
| `pages_read = 0` | `health.skipped_pages` | 整份都认不出 → 版式假设崩了（1/3/4/8/10 类） |
| 中间某页被跳过 | 同上 + `pages/pNN_原页.png` | 单页异常 → 2/6 类，或那页真是广告 |
| 能读但错误数离谱 | `pages[].findings` | 读数错 → 5/7 类 |
| `thin_months` 非空 | `cells.csv` | 切分漏格 → 2 类 |
| `shape_groups` 远大于 12 | `health.shape_groups` | 字形被切碎 → 6 类 |
| `min_conf < 0.25` | `cells.csv` 的置信度列 | 形状分组糊了 → 6 类 |

经验：**标注图（`pNN_标注.png`）比任何数值都好用**。框画到整页、画到白纸上、画到表头、串成一长条——每种错位指向不同根因。

## 一、常见 10 类根因

### 1. 整页白底矩形把全页并成一块
症状：0 个字形 / `pages` 全是 skip / `glyphs` 极少。
原因：设计稿常铺一个 100% 白底矩形，轮廓“贴得近”就 union-find 成整页一大块。
判据：某轮廓宽高 ≥ 90% 页尺寸，或面积 ≥ 45% 页面积。
修复：`extract.py::_is_background`。新增判据时别只看颜色，要同时看尺寸占比。

### 2. 表格线把相邻数字串成一长条
症状：`thin_months`；某月只切出一半格子；标注图里框横跨整块。
原因：日历块的框线（极细极长）把整行、整列、甚至整块的字连成 1 个 item。
判据：`min(w,h) ≤ 1.4` 且 `max(w,h) ≥ 8`，或“一根短线配一根长线”。
修复：`extract.py::_is_line`；并且 `collect_items` **只在同色轮廓间合并**（按 `_color_key`
分桶）——红黑混排的稿子如果只按单色取墨点，会只抓到一半数字。

### 3. 一格里除了日期还有农历 / 节日名 / 休班标记
症状：读数出现 “244”、“135” 这种三字符；或 `shape_groups` 暴涨。
原因：把整格字形拼成字符串再读。
修复：`layers.py::date_glyphs(gs)` —— **只取格内最左边 1~2 个字形**；读数 > 31 时
退化为只读第一位。凡涉及“投票取名字 / 估计字母表 / 读数”的地方都必须走
`date_glyphs`，不要直接遍历整格。

### 4. 首行左上角是上个月的末尾日期
症状：整月错位一格；1 号被读成 30/31；`pos_ok` 大面积 False。
原因：多数台历把上月末的灰字（27~31）排在本月首行前面。
修复：`layers.py::_run_from` + `assign_days` —— 用“连续日期串”找 1 号起点，
起点之前的格子标 `PREV(-1)`，对账时整格忽略；**但编号仍按位置公式**
`(r-r0)*7+(c-c0)+1`，不能改成“断了就停”（否则漏印的 23 日会让 24~30 全变待确认）。

### 5. 墨点密度 / 字体粗细这类“长相判据”误杀细笔画数字
症状：个别数字读成邻居（17 读成 1）；`min_conf` 掉。
原因：某些字体的 “7” 只有两道细线，被“密度 < 3”的阈值干掉。
修复：**已删掉密度阈值**（只留 0.8 的噪点地板）。不要把它加回来；
要过滤就用“位置 + 顺序”，不要用长相。

### 6. 装饰物碎片撑出假行 / 带偏列中心
症状：编号整体偏移；`rows` 比实际多一行；列中心偏。
原因：logo 碎片、右上角装饰、周数列被当成日期行/列。
修复：`layers.py::_prune_rows`（只在“顶行间距明显小于行距”时判为规律性，
别用“格子太多就砍行”）、`layers.py::_column_centers`（**只用字数 ≥ 5 的密行估列**）。

### 7. 置信度口径太严，正确读数被报成待确认
症状：`n_warn` 一片；`min_conf` 在 0.6~0.8，但读数其实全对。
原因：用“第一名占比”当置信度，在字形相近（6/8/9）时会误报。
修复：`cluster.py::label_by_position` 返回 **margin（第一名领先第二名多少）**，
`check.py::MIN_CONF = 0.25`。不要退回占比口径。

### 8. 整页是位图（图片）
症状：`skip` 原因写着“这一页的字形太少”。
修复：位图页由 `raster.py::glyphs_from_bitmap` 从像素切字（大津法阈值 + 投影切段），
之后认形状、投票命名、对历法完全通用。如果仍失败，优先怀疑：
图片太小（字不到 12px）、背景有花纹/渐变、或者不是一页一个月。
**不要**为了图片去引入 OCR 模型或字体模板匹配：前者要联网下模型，后者换字体就废。

### 9. 两头都印别月灰字的“满格”版式
症状：`need_ai=true`、`min_conf` 掉到 0.1 以下、几乎每格都报“位置印错了”；但标注图里框画得整整齐齐。
原因：首行左侧印上月尾、末行右侧印下月头，整张网格 6 行 42 格**格格有字**。
从哪一格起数都不会断，“日期串最长”分不出 1 号在哪，只能退回左上角，整月错位。
修复：`layers.py::_fringe_start` —— 两头格数由历法算得出（首行左侧 = 1 号之前几天、
末行右侧 = 排满整周后的空格），再要求两头是**浅灰字**、1 号那格是本色；
`pipeline.py` 第 2.5 步先用这两条把“第一列是周几”定下来。字号/颜色取不到时
一律返回 `None` 退回老办法，**不会把真排错的稿子改对**。
配套：串末尾的下月头标 `NEXT(-2)`（`PREV(-1)` 只覆盖上月尾），
`check.py` 里“重号 / 超范围 / 星期对位”都要跳过它。

### 10. 通用判据全都不认识的怪版式（连排换行 / 环形 / 异形）
症状：某页 `page_linear` 与 `page_structure` 都 `ok=False`，但人眼看着确实是月历。
处理：**不要为这一款去加规则**。正确路径是版式档案：
1. `profile.py::learn_flow` 在“哪几行是日期行 / 每行步距多少”上做小范围试算；
2. 试算成功的切法必须自证：1~9 一位数、10 往后两位数的字形个数分布要对
   （`_pattern_ok`），每槽 ≤ 2 字、格距要匀（`_slot_ok`）；
3. `pipeline.py` 第 4.5 步再拿历法验一次：读数与历法不符的格数超过 `max(3, 12%)`
   就整页跳过并写明“这次跳过、不当成错误”，**绝不把假错误丢给用户**；
4. 自证通过后才 `save` 存档，下次同款直接 `match + read_by_profile` 命中。
注意：档案里只存“行 y + 格距”，**不存“第一格的绝对 x”**（月初留空会让绝对位置换年就错位）。

## 二、定位手法的效率顺序

1. `result.json` 的 `health` + `skipped_pages`（30 秒，先归大类）
2. `pages/pNN_原页.png`（看版式，10 秒）
3. `pages/pNN_标注.png`（看引擎把框画到哪，最快暴露错位）
4. `cells.csv`（真要改代码时看，按行列排，一眼看出哪行哪列开始错）
5. 只有以上都不够，才去写临时脚本打内部量（`page_structure` 的 score / cols / cells 明细）

## 三、改完必须验的三类稿

任何改动都要三类一起跑，缺一类都不算修好：

| 稿子 | 要看的是 |
|---|---|
| 七列网格稿（带上面月尾灰字的版式） | 月份对得上、首行灰字不被当成 1 号 |
| 横排稿（一行 / 两行连排） | 槽数 = 当月天数，槽位从左到右连续 |
| 合成回归稿（`tools/make_sample.py` 生成，无客户信息） | 错处要被抓出来，且不新增待确认 |

命令：

```bash
<解释器> scripts/run_check.py "<稿子>" --year 2027 -o /tmp/verify --diag --png
```

三类都对，再向用户交付；有一类退化，就回退，不要带着新 bug 上线。

## 四、不要做的事

- 不要为了“让这一份稿子过”去放宽全局阈值（把 `MIN_CONF` 调到 0.1、把格子数档放大一圈）。
  一份过、十份崩，是这类工具最常见的死法。
- 不要用“格子数太多就砍行 / 太少就丢页”这种粗暴分支（已踩过：31 天月份首行被砍、
  5 字形格子被整格丢弃）。
- 不要引入 OCR / 字体模板匹配（前者要模型依赖，后者遇到新字体就废）。
- 不要在 Skill 的 `engine/` 里手改而不回写仓库；两边必须同一份（用 `scripts/sync_engine.ps1`
  同步，跑完看 `result.json` 里的 `engine` 指纹是否一致）。
